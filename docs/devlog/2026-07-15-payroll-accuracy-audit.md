# 2026-07-15 급여 정확성 감사

## 목표

급여 숫자가 실제로 어떤 입력과 경로에서 계산되는지 추적하고, 법적 기준 문제와 일반 계산 버그를 분리해 우선순위를 정했습니다.

## 범위

- `Utils/Payroll.swift`
- 사장님 홈, 직원 관리, 월별 정산 화면
- 알바생 홈, 출퇴근, 캘린더, 내역 화면
- `workers`, `work_logs` 스키마와 급여 관련 migration
- 현재 테스트 타깃

## 발견 사항

| 우선순위 | 발견 | 사용자 영향 | 감사 당시 상태 |
|---|---|---|---|
| P0 | 3.3%와 4대보험을 배타적인 공제 방식으로 처리 | 근로소득세 누락 또는 소득 구분 오류 | 미해결 |
| P0 | 현재 시급/설정으로 과거 승인 급여 재계산 | 조건 변경 후 과거 금액 변동 | 미해결 |
| P1 | 월 안의 실제 시간만으로 주휴수당 추정 | 월 경계, 개근, 소정근로시간 오판 | 미해결 |
| P1 | 최저임금 저장 방어 없음 | 잘못된 시급 입력 허용 | 미해결 |
| P1 | 화면마다 세전/세후 합산 항목 불일치 | 세후가 세전보다 크게 보일 수 있음 | 미해결 |
| P1 | 출근 중 시간과 예상 급여 갱신 기준 불일치 | 실시간 급여가 멈춰 보임 | 미해결 |
| P2 | 일부 내역 화면에서 야간수당 설정 전달 누락 | 화면별 급여 불일치 | 점검 필요 |

## 테스트 상태

감사 당시 `HowMuchTodayTests.swift`에는 `XCTAssertTrue(true)` smoke test 하나만 있었습니다. 당시 빌드 성공은 컴파일 가능성만 의미했고 계산 정확성을 보장하지 못했습니다.

## 후속 개선 (2026-07-17)

- 근무 기록 생성 시 적용 시급과 야간수당 여부를 DB 트리거로 스냅샷합니다.
- 과거 시급 스냅샷, 레거시 fallback, 야간수당 계산 회귀 테스트를 추가했습니다.
- 화면의 늦게 도착한 응답을 차단하는 최신 요청 검증 테스트를 추가했습니다.
- 현재 단위 테스트 5개가 통과하며, 나머지 급여 모델과 RLS 통합 테스트는 계속 보강합니다.

## 결정

부분적인 화면 보정보다 계산 입력/출력 계약과 데이터 모델을 먼저 고칩니다.

1. 소득 구분과 공제 항목 모델 분리
2. 근로조건 버전과 승인 결과 스냅샷
3. 주휴수당 입력 모델 재설계
4. 화면 계산 경로 통합
5. 경계값/회귀 테스트 추가
