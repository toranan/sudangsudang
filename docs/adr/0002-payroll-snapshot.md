# ADR 0002: 근무 기록에 적용 시급 스냅샷 저장

- 상태: Accepted
- 결정일: 2026-07-15

## Context

`work_logs`가 현재 `workers.hourly_wage`와 야간수당 설정으로 다시 계산되어, 시급을 바꾸면 이미 생성된 근무의 급여도 바뀌는 문제가 있었습니다. 다만 현 단계에서 법정 급여 전체를 확정하는 정산 엔진까지 도입하는 것은 범위가 큽니다.

## Decision

`work_logs`에 `applied_hourly_wage`와 `applied_night_allowance`를 저장합니다.

- `BEFORE INSERT` 트리거가 해당 `worker`의 현재 값을 복사합니다.
- 기존 기록을 승인하거나 시각을 수정해도 기존 스냅샷을 유지합니다.
- 급여 화면은 스냅샷을 우선하고, 없는 레거시 응답에서만 현재 `workers` 값을 fallback으로 사용합니다.
- `workers.hourly_wage`와 야간수당 설정 변경은 변경 후 새로 생성되는 근무부터 적용됩니다.

## Alternatives

- 현재 설정으로 항상 재계산: 과거 결과가 바뀌어 제외했습니다.
- 유효기간 근로조건 테이블: 정교하지만 현재 필요보다 스키마와 조회 복잡도가 커 보류했습니다.
- 승인 시 총액 스냅샷: 확정 정산에는 적합하지만, 근무 시각 정정 후 재계산 이력 설계까지 필요해 보류했습니다.

## Consequences

- 시급과 야간수당을 포함한 승인 근무의 세전 금액은 후속 설정 변경의 영향을 받지 않습니다.
- 마이그레이션 전 시급 이력은 없으므로 기존 기록은 실행 시점의 `workers` 값으로 한 번 보정합니다.
- 주휴수당과 공제는 아직 현재 설정에 따른 예상치입니다. 확정 정산을 제공할 때는 별도 정산 스냅샷이 필요합니다.

## Rollout

1. `20260715_reconcile_worker_payroll_columns.sql`을 앱 배포 전에 적용합니다.
2. 기존 기록을 현재 `workers` 값으로 보정하고 제약 조건을 겁니다.
3. 사장님과 알바생 급여 화면을 스냅샷 우선 계산으로 배포합니다.
4. 시급 변경 전·후 기록의 계산 회귀 테스트를 유지합니다.
