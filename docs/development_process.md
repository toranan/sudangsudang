# 개발 및 개선 과정 기록

이 문서는 포트폴리오에서 "무엇을 만들었는지"보다 "왜 그렇게 만들었는지"를 보여주기 위한 기록 방식입니다.

## 기록 원칙

기능을 만들 때마다 아래 5가지를 짧게 남깁니다.

1. 문제: 사용자가 어떤 상황에서 불편했는가
2. 목표: 이번 개선으로 어떤 상태가 되어야 하는가
3. 결정: 어떤 설계/기술/UI를 선택했는가
4. 구현: 실제로 어떤 파일과 로직을 바꿨는가
5. 검증: 빌드, 테스트, 수동 확인 결과는 무엇인가

포트폴리오에 올릴 때는 기능 목록만 늘리지 않고, "문제 -> 판단 -> 구현 -> 검증 -> 남은 리스크" 순서로 남깁니다. 이 순서가 있어야 채용자가 결과물뿐 아니라 개발 과정의 사고 흐름을 볼 수 있습니다.

## 추천 기록 단위

- 큰 기능: 별도 섹션으로 기록
- 작은 UI 개선: 날짜별 변경 로그로 기록
- 버그 수정: 원인/해결/재발 방지 중심으로 기록
- AI/RAG 개선: 검색 정확도, 답변 품질, fallback, 비용 관점으로 기록

## README 반영 기준

- 사용자에게 직접 의미 있는 변화만 README의 주요 기능에 올립니다.
- 구현은 되었지만 아직 안정화가 필요한 항목은 "개선 예정"으로 분리합니다.
- 내부 구현 파일은 핵심 파일만 적고, 전체 파일 목록처럼 만들지 않습니다.
- 검증하지 않은 성능 수치, 사용자 수, 배포 상태는 적지 않습니다.
- 민감한 키, 실제 운영 URL, 개인 계정 정보는 README와 커밋에서 제외합니다.

## 2026-07-10 매장별 RAG 챗봇

### 문제

가게마다 마감 순서, 포스기 사용법, 공지사항이 다르지만 알바생은 매번 사장님에게 물어보거나 단톡방 과거 메시지를 찾아야 했습니다. 사장님 입장에서도 반복 질문이 쌓이고, 매뉴얼이 있어도 실제로 읽히지 않는 문제가 있었습니다.

### 목표

- 사장님이 공지와 매뉴얼을 직접 등록한다.
- 알바생은 본인이 속한 매장의 공지/매뉴얼만 읽을 수 있다.
- 모르는 내용은 챗봇에 질문하고, 챗봇은 해당 매장 문서만 근거로 답한다.
- 정확도가 중요한 영역이므로 매장 간 문서 섞임을 막는다.

### 구현

- `supabase/migrations/20260708_store_documents.sql`
  - `store_documents` 테이블 추가
  - `embedding vector(1536)` 컬럼 추가
  - owner manage / worker view RLS 정책 추가
  - `match_store_documents` RPC 추가
- `supabase/functions/store-rag/index.ts`
  - `index`: 문서 저장/수정 시 임베딩 생성
  - `ask`: 질문 임베딩 생성 후 매장별 유사 문서 검색
  - Gemini 답변 생성
- `Features/Owner/StoreKnowledgeManagementView.swift`
  - 사장님용 공지/매뉴얼 관리
  - 문서 상세 보기, 수정/삭제 메뉴
  - 챗봇 UI
- `Features/Worker/WorkerStoreKnowledgeView.swift`
  - 알바생용 읽기 전용 공지/매뉴얼/챗봇

### 의사결정

- 외부 Vector DB 대신 Supabase pgvector를 사용했습니다.
  - 이유: MVP 단계에서 인프라를 늘리지 않고 RLS와 DB 권한 모델을 한 곳에서 유지하기 위해서입니다.
- 사장님 화면과 알바생 화면을 분리했습니다.
  - 이유: 같은 화면을 재사용하면 알바생에게 수정/삭제 기능이 노출될 위험이 있어 권한 혼란이 생깁니다.
- 챗봇은 일반 메신저 형태로 만들었습니다.
  - 이유: 사용자가 이미 익숙한 패턴이고, 입력창 위치가 예측 가능하기 때문입니다.

### 검증

- Edge Function deploy 완료
- Supabase migration 적용 완료
- `xcodebuild` iOS Simulator generic build 성공
- `git diff --check` 통과

### 남은 개선

- 답변에 문서 출처를 더 명확한 UI로 표시
- 문서가 없는 상태에서 질문할 때 더 자연스러운 안내
- PDF/이미지 문서 업로드와 자동 청킹
- RAG 답변 품질 평가용 샘플 질문 세트 추가

## 2026-07-10 알바 홈 UX 개편

### 문제

알바 홈은 여러 매장이 카드로 나열되어 있어, 사용자가 어느 매장을 기준으로 보고 있는지 빠르게 인지하기 어려웠습니다. 사장님 화면은 매장 드롭다운 중심으로 정리되어 있었기 때문에 양쪽 역할의 UX 구조도 달랐습니다.

### 목표

- 알바생도 매장을 드롭다운으로 선택한다.
- 선택된 매장을 기준으로 급여, 출퇴근, 공지/매뉴얼/챗봇을 본다.
- 사장님 화면과 유사한 정보 구조를 유지한다.

### 구현

- `WorkerHomeView.swift`
  - `selectedStoreId`, `isStoreDropdownExpanded` 상태 추가
  - 선택 매장 드롭다운 추가
  - 선택 매장 급여 요약 카드 추가
  - `출근/퇴근하기`, `공지 · 매뉴얼 · 챗봇` 빠른 메뉴 추가
  - 데이터 새로고침 후 선택 매장 보정 로직 추가

### 검증

- `xcodebuild` iOS Simulator generic build 성공
- `git diff --check` 통과
