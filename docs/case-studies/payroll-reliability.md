# 급여 계산 신뢰성 개선

> 상태: 1차 개선 완료 - 시급·야간수당 스냅샷

## 문제

화면에는 예상 급여와 공제액이 구체적인 숫자로 표시되지만, 계산 모델과 데이터 구조가 그 정밀도를 보장하지 못했습니다. 특히 설정을 바꾸면 과거 승인 급여가 달라질 수 있어 사용자 신뢰에 직접 영향을 줍니다.

## 발견한 원인

1. `3.3% 원천징수`와 `4대보험`을 배타적인 공제 방식으로 모델링했습니다.
2. 근무 기록에 적용 시급, 수당, 공제 기준이 저장되지 않고 현재 `workers` 설정으로 다시 계산됩니다.
3. 주휴수당을 월 안의 실제 근무시간 합계만으로 추정합니다.
4. 시급 저장 시 최저임금 범위 검증이 없습니다.
5. 화면마다 기본급, 야간수당, 주휴수당을 합산하는 범위가 다릅니다.
6. 출근 중 근무시간은 증가하지만 예상 급여가 같은 기준으로 갱신되지 않습니다.
7. 일부 연결 매장의 야간수당 설정이 내역 화면까지 전달되지 않습니다.

상세 재현 경로는 [감사 로그](../devlog/2026-07-15-payroll-accuracy-audit.md)에 기록했습니다.

## 검토한 선택지

### 근무 기록에 핵심 계산 조건을 저장

시급과 야간수당 적용 여부를 `work_logs`에 복사하면 현재 문제를 작은 변경으로 막을 수 있습니다. 다만 확정 정산 결과 전체를 재현하지는 못합니다.

### 유효기간 근로조건만 저장

변경 이력은 표현할 수 있지만 법정 요율이나 계산 코드가 바뀌면 과거 결과가 달라질 수 있습니다.

### 유효기간 근로조건 + 정산 스냅샷

근무 당시 조건과 승인된 계산 결과를 함께 보존할 수 있습니다. 저장 공간과 마이그레이션 비용이 늘지만 급여의 재현 가능성이 가장 높습니다.

## 결정 방향

현재 사용자 문제에 필요한 시급과 야간수당 적용 여부만 `work_logs`에 저장하는 단계적 접근을 선택했습니다. DB 트리거가 근무 기록 생성 시 값을 복사하고, 이후 승인·시각 수정에서도 이 값을 보존합니다. 정산 기능이 필요해질 때 근로조건 버전과 총액 스냅샷으로 확장합니다. 세부 결정은 [ADR 0002](../adr/0002-payroll-snapshot.md)에 기록했습니다.

## 1차 구현

1. 운영 DB에 누락된 `workers.apply_night_allowance`와 `payday`를 멱등적으로 보정했습니다.
2. `work_logs` 생성 시 적용 시급과 야간수당 여부를 저장하는 트리거를 추가했습니다.
3. 기존 기록은 마이그레이션 시점의 `workers` 설정으로 한 번 보정했습니다.
4. 사장님 홈·통계·직원 상세와 알바생 홈·내역·캘린더가 같은 공통 계산 함수를 사용하도록 바꿘습니다.

## 검증

- 22:00~06:00 야간 근무 8시간의 기본급과 50% 할증 계산 통과
- 과거 시급 10,320원 스냅샷이 현재 시급 11,000원보다 우선되는 회귀 테스트 통과
- 스냅샷이 없는 레거시 응답의 fallback 테스트 통과
- 서명 없는 iOS Debug 빌드 통과

## 결과

1차 범위인 시급·야간수당 재현은 구현했습니다. 이후 시급을 바꿔도 변경 전 근무의 세전 금액은 생성 당시 조건을 유지합니다. 주휴수당·공제는 아직 예상치이며, 확정 정산으로 확장할 때 별도 스냅샷을 도입합니다.
